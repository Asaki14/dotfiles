# Project Deliverables

处理需求 brief、报告、正式交付生命周期、Phase 或迁移映射时读取对应章节。

## 需求 brief

简单需求直接进入 `ROADMAP.md`。需要稳定契约时，路径与目录升级遵循 [`STRUCTURE.md`](STRUCTURE.md) 的“分类与命名”，正文使用：

```markdown
# REQ-<date>-<topic>

- 提出方：
- 决策对象：
- 背景：
- 目标：
- 非目标：
- 交付物：
- 验收标准：
- 数据与证据边界：
- 截止时间：
- 依赖：
- 风险：
- Roadmap：`../ROADMAP.md#<anchor>` <!-- 位于 sources/ 时；迁入子目录后同步调整 -->
```

## Reports 与 Derived

- 面向决策者的叙事、结论、建议和正式呈现属于 report。
- 结论—证据映射、摘录、清洗、统计、审计、复算输入和研究过程索引属于 derived。
- 报告引用 derived；证据加工文件保留在 sources，不复制进报告包。
- 同一文件同时包含正式叙事和大量可复算加工时，拆分为 report 与 derived 并相互链接；不可分割时按主要用途归类。
- Derived 记录输入路径、方法、对象、时间窗、局限和复算方式；可跨阶段复用的证据加工属于 derived。

## 正式交付生命周期

正式交付区只保留当前可交付版本。旧交付按价值裁定：

1. 仍需交付：更新正文、证据和导航，使其成为现行版本；
2. 仅供历史复盘：移动为真实 phase 材料，并从正式交付导航移除；
3. 无保留价值且用户确认删除：删除并记录迁移映射。

文件名中的 `old`、`v2` 或说明文字不改变其生命周期属性。

## Phase

- 值得版本化的阶段草稿、工作矩阵、评审、验收或历史材料可以落盘；放置路径和局部 INDEX 资格遵循 [`STRUCTURE.md`](STRUCTURE.md)。
- Phase 文件或目录名对应 `ROADMAP.md` 的阶段标识与名称。
- 正式交付保留在正式交付路径；Phase 链接正式交付。
- 仅含 INDEX、占位文件或空目录的 Phase 不构成阶段材料。

需要局部 INDEX 时使用：

```markdown
# P<N> <阶段名>

- Roadmap：`../../ROADMAP.md#<anchor>`
- 目标：
- 范围：
- 非目标：
- 输入：
- 阶段中间产物：
- 正式交付：
- 退出条件：
```

Phase INDEX 保存稳定上下文；执行状态、待办和完成日期保留在 `ROADMAP.md`。

## 迁移映射

`outputs/INDEX.md` 的迁移映射逐文件记录：

- 每个旧文件单独一行，写出完整原路径和当前路径；
- 合并时，每个原文件各写一行并指向同一当前文件；
- 拆分时，同一原文件分别指向每个当前文件；
- 删除时，当前路径写 `—` 并记录依据；
- 仅目录被删除且目录内没有文件时，使用目录级映射。

路径必须显式展开；通配符、`{a,b}`、`<同名>`、`同目录` 和目录概括不能代替文件级映射。
