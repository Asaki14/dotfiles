# Project Scaffold Validation

设计方案和最终验收均完整读取本文件。方案阶段为每项标记“适用 / 不适用”及理由；执行后记录命令输出或文件证据。

| 检查面 | 最低检查对象 | 通过条件 |
|---|---|---|
| 治理职责 | 仓库内 README、CLAUDE、AGENTS，根目录治理文件，两级全局 INDEX | 根 README 与根 CLAUDE 分别是唯一入口；规则、状态和正文元数据各有唯一来源 |
| 目录层级 | 空目录、唯一子目录、单文件子目录、跨分类同名主题目录 | 每个保留目录均有当前可验证边界 |
| 局部 INDEX | 根目录之外全部 INDEX | sources/outputs 全局 INDEX 存在；其他 INDEX 提供不可替代的范围、顺序或维护信息 |
| Phase | phase 内容、文件或目录名、可选 INDEX、Roadmap 链接 | 单材料直接放 outputs；名称一致；可选 INDEX 有导航价值且锚点有效；状态只在 ROADMAP |
| 正式交付 | 正式导航、产物路径、版本关系 | 路径语义稳定且不绑定阶段；只导航现行版本；旧版本已有生命周期裁定 |
| Markdown | 全部本地文件链接、相对路径、标题锚点 | 目标存在；锚点按实际渲染规则可达 |
| 迁移引用 | 全文旧路径搜索、迁移映射 | 旧引用仅存在于迁移历史；映射逐文件显式展开 |
| 软链 | 仓库内全部 symlink | 目标存在；兼容入口已经用户确认 |
| HTML | `src`、`href`、CSS URL、脚本和构建后的本地引用 | 本地目标存在；移动后仍可加载 |
| 工具 | 脚本默认输入输出路径、配置、文档命令、构建入口 | 默认执行使用当前路径；命令可运行 |
| 报告 | DESIGN Validation、结构、数据、roundtrip、渲染、证据标签与邻近 Source note | 适用规范通过；事实与来源关系可追溯 |
| Git | upstream、未推送 commit、未提交工作区、回滚基线 | 四类状态分别展示；既有成果可定位；提交与推送由用户决定 |
| 通用质量 | 项目测试、格式检查、`git diff --check` | 全部通过，或阻塞有具体证据和外部动作 |

不适用项记录理由，不生成虚假检查结果。
